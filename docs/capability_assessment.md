## FoldBounds

The executable Python package implements a finite two-dimensional hydrophobic/polar lattice model. Its state space consists of self-avoiding walks with the first edge fixed from `(0,0)` to `(1,0)`; reflected walks remain distinct. Energy is proportional to nonconsecutive H–H contacts. The exact rational parameter is `q >= 1`; the program does not infer it from experiments.

## Safe evaluation interface constraints

1. Never execute subject tests/builds with their checkout as a writable working directory. Use isolated copies under SVB when a subject can write caches; set `PYTHONDONTWRITEBYTECODE=1`. Do not import modules that auto-build without controlling the fallback.
2. FoldBounds CLI is a narrow real interface: `python -m foldbounds <sequence> --q <rational> --depth <n> --event-at-least <k>`. It emits rational interval strings. Use a new working directory and read-only package path or isolated copied sources. Impose small sequence bounds and subprocess timeouts.
3. PCS receiver-owned compiled authority can be addressed explicitly; no missing-binary fallback should build inside the subject checkout. Full v0.6 package evaluation also needs a valid independent producer package/key/trust contract. Merely calling `assess_claim` is a real metadata evaluation but must not be reported as an end-to-end Lean package test.
4. Website pure `.mjs` calculation/report modules can run under Node in an isolated harness. Do not dispatch public jobs or call production APIs. A pure-module test is not a browser journey or full service evaluation.
5. The inspected website pins a different historical core revision for public jobs than PCS checkout HEAD. Record and respect that fact; do not silently call a latest-PCS local result a replay of a pinned hosted job.

## What this assessment can and cannot establish

The inspected implementations supply concrete capability-specific targets and explicit limitations, making meaningful noninvasive measurements feasible. They do not provide independent ground truth for SVB, prove every informal claim made in documentation, establish clinical/biological adequacy, or justify a combined PCS/FoldBounds leaderboard. General scientific reasoning tasks should be scored separately from these narrow adapters, with unsupported capability and execution failure visible. Successful package validity, finite bound containment and honest scope reporting must be separate metrics.
