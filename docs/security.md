# Execution and data boundary

The core evaluates JSON responses as inert data. It never launches a submitted program, shell command, proof script, plugin or URL. A textual instruction in a reason or document does not change grading. Input is capped at 2 MB, duplicate keys and nonfinite values are rejected, paths are confined to registered in-project source data, source SHA-256 must match, and failed executions cannot assert a label. Reference checkers are fixed maintained code for the frozen pilot, not an extensible untrusted expression language.

Optional adapters run only explicitly named local tools from the three subject checkouts, with 30-second subprocess timeouts, a minimal environment excluding tokens/proxy credentials, bytecode writes disabled, a project-local working directory and temporary directories inside the new project. They never build or install dependencies in subjects. The adapter checks captured output size after process completion, so it is not a hard memory limit. These controls are NOT an OS sandbox and are NOT safe for arbitrary submitted executable systems. General executable submissions are unsupported until container/VM isolation, hard CPU/memory/output limits, read-only mounts, network denial and secret separation are implemented and tested. The JSON-only core is the supported external submission interface.

No production endpoint was tested, no database was changed, no private model/API was called, and no paid service was used. Raw subject fixture copies were temporary under the independent project and removed. Verbose optional-adapter execution and full private source-tree fingerprints remain gitignored in results/local; tracked results contain sanitized numeric measurements and source identities. They do not include subject source code, credentials or private datasets.

Public Iris and PDB source files are redistributed under the license records in data/registry.json, distinct from Apache-2.0 project code. Reproduction of optional adapters requires authorized access to corresponding subject checkouts and PCS's precompiled binary. No bundled subject code is necessary for the independent core.
